# Deployment checklist — Render + Qdrant Cloud

CircuitSage deploys from [`render.yaml`](../render.yaml) (Render Blueprint): a managed
PostgreSQL, the API (Docker) with a pre-deploy migration, the ingestion/eval worker (Docker),
and the React SPA as a static site. The vector index lives on **Qdrant Cloud**, wired in via
environment variables.

> No plaintext secret is committed. Render generates `JWT_SECRET`; OpenAI and Qdrant
> credentials are entered in the dashboard (`sync: false`); the database URL is injected from
> the managed database. CORS uses an exact origin, never a wildcard.

## 0. Prerequisites

- [ ] A Render account and this repository connected to it.
- [ ] A Qdrant Cloud cluster (note its URL and API key).
- [ ] A real OpenAI API key and a real, available chat/embedding model id.
- [ ] Local verification is green: `bash scripts/smoke_test.sh`, backend tests + coverage,
      `npm run build`, and both `docker build`s (see the README).

## 1. Provision Qdrant Cloud

- [ ] Create a cluster; copy the endpoint (e.g. `https://<id>.<region>.cloud.qdrant.io:6333`)
      and an API key.
- [ ] The collection (`circuitsage_chunks_v1`, 1536-dim cosine) is created by the app/worker on
      first ingest; no manual setup needed.

## 2. Create the Render Blueprint

- [ ] In Render: **New → Blueprint**, point at this repo. Render reads `render.yaml` and plans
      `circuitsage-db`, `circuitsage-api`, `circuitsage-worker`, and `circuitsage-web`.
- [ ] Review the plan. Adjust `plan:` / `region:` values if those slugs are not available on
      your account.

## 3. Set secret environment values (dashboard, never committed)

In the **circuitsage-secrets** env var group, fill the `sync: false` values:

- [ ] `OPENAI_API_KEY` — your real key.
- [ ] `OPENAI_CHAT_MODEL` — a real model id (replaces the spec placeholder `gpt-5.6-luna`).
- [ ] `QDRANT_URL` — the Qdrant Cloud endpoint.
- [ ] `QDRANT_API_KEY` — the Qdrant Cloud key.

`JWT_SECRET` is generated by Render automatically. `DATABASE_URL` is injected from
`circuitsage-db`.

## 4. Confirm URLs and CORS

Render assigns hostnames on first deploy. If they differ from the defaults in `render.yaml`:

- [ ] Set the API's `FRONTEND_ORIGIN` to the **exact** web origin (e.g.
      `https://circuitsage-web.onrender.com`) — no trailing slash, no wildcard.
- [ ] Set the web build's `VITE_API_BASE_URL` to `https://<api-host>/api/v1` and redeploy the
      static site (the value is baked in at build time).

## 5. Deploy & migrate

- [ ] Trigger the deploy. The API's **pre-deploy command** runs
      `alembic -c alembic.ini upgrade head` (through the image entrypoint, which normalizes the
      `DATABASE_URL` scheme to `+psycopg`).
- [ ] Create the first admin once the API is live (Render Shell on the API service):
      `python -m app.cli create-admin --email you@example.com`.

## 6. Post-deploy smoke

- [ ] Readiness & basic checks:
      `PROD=1 API_BASE_URL=https://<api-host> bash scripts/smoke_test.sh`
      — `/health/ready` must be `200` (DB + Qdrant reachable); `/version` returns the build.
- [ ] Open the web URL, sign in, upload a small PDF, wait for it to index, and ask a question.

## 7. Rollback

- [ ] Render keeps deploy history per service — use **Rollback** to the previous successful
      deploy. Migrations are additive; avoid destructive down-migrations in production.

## Environment variable reference

| Variable | Where | Source | Notes |
|----------|-------|--------|-------|
| `APP_ENV` | api, worker | value `production` | Enables HSTS, disables `/docs`. |
| `DATABASE_URL` | api, worker | `fromDatabase` | Scheme normalized to `+psycopg` by the entrypoint. |
| `JWT_SECRET` | api, worker | `generateValue` | ≥32 chars; shared via the env var group. |
| `OPENAI_API_KEY` | group | `sync: false` | Secret. |
| `OPENAI_CHAT_MODEL` | group | `sync: false` | Real model id. |
| `OPENAI_EMBEDDING_MODEL` | api, worker | value | `text-embedding-3-small`. |
| `EMBEDDING_DIMENSIONS` | api, worker | value | `1536` (must match Qdrant collection). |
| `QDRANT_URL` | group | `sync: false` | Qdrant Cloud endpoint. |
| `QDRANT_API_KEY` | group | `sync: false` | Secret. |
| `QDRANT_COLLECTION` | api, worker | value | `circuitsage_chunks_v1`. |
| `FRONTEND_ORIGIN` | api | value | **Exact** web origin for CORS. |
| `ALLOW_REGISTRATION` | api | value `false` | Admin-created accounts only in prod. |
| `VITE_API_BASE_URL` | web (build) | value | Absolute API base baked into the SPA. |
| `PORT` | api | Render-provided | The API binds `$PORT` via its docker command. |

## Known deployment considerations

- **Cross-site refresh cookie.** `*.onrender.com` subdomains are on the Public Suffix List, so
  `circuitsage-web` and `circuitsage-api` are *different sites*. The refresh-token cookie is
  `SameSite=Lax`, so it will not be sent from the web origin to a different-site API origin,
  which breaks token refresh across the two default hostnames. To make auth work end-to-end,
  serve both under one registrable domain — e.g. a custom domain `app.example.com` (web) and
  `api.example.com` (API), which are same-site — or front both behind a single host/path.
  Access tokens (in memory) are unaffected; only silent refresh needs same-site.
- **Free plans sleep.** Free Render services spin down when idle; the first request after idle
  is slow. Use paid plans for a always-on demo.
- **Reranking.** The optional cross-encoder (`[rerank]` extra, torch) is **not** installed in
  the image; `reranked_hybrid` falls back to hybrid ranking in production. Install the extra and
  add resources if live reranking is required.
- **Qdrant region.** Co-locate the Qdrant Cloud region with the Render region to reduce
  retrieval latency.
